ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Проект «Лицей Чат»
Дата: 14 ноября 2026 года

1. ЦЕЛЬ

Создать настольный текстовый чат с нейросетями. Приложение должно отправлять
вопросы через RouterAI.ru, показывать ответы, хранить несколько независимых
переписок и позволять выбирать модель для каждого чата.

2. СРЕДА

Windows, Python 3.14, PyQt6, requests, SQLite и JSON. Главное окно и диалог
выбора модели задать в двух файлах .ui, открываемых Qt Widgets Designer.
Предоставить исходники для VS Code и исполняемый EXE, собранный PyInstaller.
Для работы ответов необходимы интернет, API-ключ и баланс RouterAI.

3. ИНТЕРФЕЙС

Главное окно развёрнуто при запуске. Слева — заголовок «Чаты», кнопка «Модель»,
кнопка «Новый чат» и прокручиваемый список переписок. Справа — редактируемое
название, область сообщений, многострочное поле ввода и кнопка «Отправить».
Фон чёрный, текст светлый. Верхнего меню и прикрепления файлов нет.

В поле сообщения Enter добавляет новую строку. Отправка происходит только по
нажатию «Отправить». В поле названия Enter сохраняет новое название в SQLite
и сразу меняет его в списке слева. Пользовательские сообщения показывать
справа, ответы модели — слева. Анимации ответа не нужны.

4. ЧАТЫ И МОДЕЛИ

При первом запуске создать пустой «Новый чат». Старые чаты сохранять между
запусками. Повторное нажатие «Новый чат» не должно создавать несколько пустых
чатов. Первое сообщение может автоматически стать названием нового чата.
Выбор чата показывает его историю и выбранную для него модель.

Диалог модели содержит три варианта: GPT-4o mini, GPT-5 nano и GPT-6 Luna.
Выбор сохраняется в таблице чатов и используется для следующих вопросов.
Крестик закрывает диалог без изменения модели.

5. ОТПРАВКА И ОТВЕТ

Не отправлять пустую строку. Ограничить длину вопроса 16 000 символами.
При отправке записать вопрос в SQLite, показать «Нейросеть думает…», а затем
заменить эту надпись готовым ответом. Сетевой запрос выполнять в QThread,
чтобы окно не зависало. Во время запроса отключить повторную отправку и смену
чата. В контекст передавать последние десять пар сообщений; всю историю
оставлять в локальной базе.

Понятно показывать ошибки отсутствующего ключа, сети, ожидания, баланса и
недоступной модели. Ошибочный запрос исключать из следующего контекста.
Не показывать выдуманный ответ вместо ошибки.

6. ХРАНЕНИЕ

Автоматически создать две SQLite-таблицы:
chats(id, title, model, created_at);
messages(id, chat_id, role, text, status, created_at).
messages.chat_id — внешний ключ на chats.id. SQL-запросы параметризованы.
Сохранять ключ и модель по умолчанию в отдельном settings.json.

7. КОМПЛЕКТ И ПРОВЕРКА

Передать пять Python-файлов, две формы .ui, requirements.txt, настройки с
отдельным тестовым ключом, инструкцию, ТЗ, пояснительную записку, план защиты
и EXE. Базу с личной историей переписок в ZIP не включать.

Проверить запуск из VS Code и EXE, создание и переименование чатов, выбор
модели, перенос строки по Enter, ответ RouterAI, сохранение истории после
перезапуска, обработку сетевой ошибки и читаемость интерфейса.
